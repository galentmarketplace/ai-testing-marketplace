# Production-Readiness Gap Analysis — AI Testing Marketplace

_Generated 2026-09-23 from a file-by-file survey of this repository plus a review of the reference products (Shiplight, QA Wolf, Momentic, Autify/mabl, Playwright Test Agents, EarlyAI/Qodo, Vibium) and SaaS readiness standards (SOC 2 TSC, OpenTelemetry GenAI conventions). Line references are `file:line` at commit `69da61f`. The three Blocker findings were independently re-verified against the code before publication._

## 0. Headline

The agent core is genuinely differentiated: a registry-driven scheduler, DOM/accessibility-grounded Playwright generation with trace-fed and oracle-gated healing, multi-methodology security exported as SARIF, k6 + Web Vitals + per-pod Kubernetes performance, and a written standards contract. **The platform shell around that core is still a single-tenant demo**: the sensitive read endpoints accept no credential, GitHub OAuth tokens sit unencrypted in SQLite, every run mutates process-global environment (so concurrent runs corrupt each other), runs execute customer code with the platform's own secrets in scope, there is no cancellation, no structured logs, metrics or LLM cost, **zero tests of the platform itself**, and the VS Code extension is a thin REST client whose only in-editor assistance is one CodeLens that re-runs a playbook. Three of those are Phase-0 blockers before any customer sees it.

Orphaned runs are marked `interrupted` on restart, never resumed. No idempotency key on `/api/run`; PR branch names are random, so a retried run creates a second branch. No timeouts for LLM steps or whole runs. | Playwright Healer: bounded loop that declares "real product bug" and stops; Momentic: step caching. | High | M |

## 2. What "co-working assistant for a testing engineer" concretely means

| # | Interaction pattern | Reference | Ours today | To build |
|---|---|---|---|---|
| 1 | **Explain this failing test** from trace/console/network/a11y snapshot, in the editor, anchored to the failing line | Playwright Healer input; QA Wolf bug reports | We already *capture* it (`e2e-runner/fixtures.ts` failure-context, `executor._failure_context`) — but only the LLM sees it | MCP `explain_failure(run_id, test)`; `@atm /explain` streaming markdown with a reference to the spec line; TestController `TestMessage` with expected/actual |
| 2 | **Heal as a reviewable diff** (never a silent rewrite), with apply / reject | Momentic shows the diff; Playwright Healer patches then reruns | Heal regenerates the whole spec and commits straight to the PR branch (`jenkins_agent.py:277-294`) | Healer returns a unified diff + oracle verdict; extension applies via `WorkspaceEdit` / "Apply fix" button, a11y snapshot shown alongside |

## 3. Phased plan

### Phase 0 — blockers before any customer demo (≈3–4 weeks, 1–2 engineers)

| # | Work item | Effort | Acceptance check |
|---|---|---|---|
| 0.1 | **API authorization**: bearer/API-token or session auth on every `/api/*`; owner check on runs, projects, artifacts; extension + MCP send the token. Remove `login IS NULL` sharing. | M | Unauthenticated `curl` to `/api/runs`, `/api/projects/<id>`, `/api/artifact` → 401; user B cannot read or delete user A's project or run (automated test). |
| 0.2 | **Encrypt OAuth tokens at rest** (reuse Fernet); move the key to env/KMS with a rotation path; cookie `secure` + `SameSite=Lax`. | S | `select token from sessions` shows `enc:`; rotation script re-encrypts and the old key is deleted. |
| 0.3 | **Run isolation**: per-run ephemeral container (Docker/K8s Job) with a **minimal env allow-list** (no platform keys), per-tenant clone dir (`repos/<org>/<run_id>`), CPU/memory limits, cleanup. Minimum viable: env allow-list + tempdir per run. | L (M minimum) | A repo whose `npm test` prints `process.env` shows no `ANTHROPIC_API_KEY`/`GITHUB_*`/`JENKINS_*`; two concurrent same-named repos don't collide. |
| 0.4 | **Remove process-global run state**: `MOCK_LLM`/`DEMO_FAIL_SUITE`/`REAL_RUNNER` become per-run config read from `state["run_config"]`. | M | Start a mock run 1 s after a live run; the live run's events show real Claude calls throughout. |
| 0.5 | **Cancellation + run timeout**: `POST /api/runs/{id}/cancel`; orchestrator checks a cancel flag between steps and passes it to subprocess/poll loops; whole-run deadline (~45 min). | S | Cancel during a Jenkins poll → status `cancelled` within 10 s, child processes gone. |
| 0.6 | **Don't mark crashed agents "done"**: record `status="error"` for the step and fail the dependent gate; surface in UI/MCP. | S | Injected exception in the Playwright agent → run ends `blocked` with a reason, not `done`. |
| 0.7 | **Platform test suite**: pytest for store (redaction, encryption, owner scoping), gates, `plan_for`, `_redact`, orchestrator loop-back; recorded-fixture tests for Jira ADF/GitHub/Jenkins clients; CI runs them. | M | ≥ 60 tests green in CI; ≥ 70 % coverage on `web/store.py`, `src/gates`, `src/orchestrator.py`. |
| 0.8 | **Structured logging + LLM cost**: JSON logs with `run_id`, `org`, `step`; capture `resp.usage` per call into `state["llm_usage"]` and `runs.tokens_in/out/cost`; show in results + MCP. | S | Every run row has token counts; `run_results` returns `cost_usd`. |
| 0.9 | Per-run artifact directory (`generated/<run_id>/…`); `/api/artifact` scoped by run + owner. | S | Two sequential security runs → both reports retrievable and different. |
| 0.10 | Demo hygiene: refresh root `README.md`; TLS in ingress; `MOCK_LLM` default 0 in the image; non-root Dockerfile user. | S | Fresh k8s deploy over HTTPS, OAuth login, one live functional run end-to-end. |

### Phase 1 — pilot with 1–2 teams (≈6–8 weeks)

| # | Work item | Effort | Acceptance check |
|---|---|---|---|

## 4. Resources to request from the product owner

**Phase 0**
- Anthropic API key in a **dedicated workspace with a spend limit** (cost metering needs a clean key).
- A **staging cluster** (k3s/OKE/EKS, 2–3 nodes) with metrics-server, ingress, TLS certificate and DNS for `PUBLIC_URL` — needed for the OAuth callback, the per-pod perf demo and sandbox Jobs.
- The **GitHub org** (`galentmarketplace` exists) with permission to create a **GitHub App** (Checks, code scanning, PR comments), plus a throwaway target repo.
- A **Jira Cloud sandbox** with a service-account token (write access) and a **Jenkins** reachable from the cluster.
- A secrets-manager decision (AWS Secrets Manager / Vault / SOPS+age) and access.
- One **security reviewer** for two days (threat model of run isolation + auth).
- 1–2 backend engineers full-time for 3–4 weeks.

**Phase 1**
- Managed **Postgres** (+ Redis, or a Postgres-only queue); an object-storage bucket for artifacts.
- **Observability stack** access: OTel collector + Grafana/Tempo/Loki, or a Datadog org.
- An **OIDC test tenant** (Okta developer org or Entra test tenant).
- **Two pilot teams**, each with a real repo (ideally one non-MERN), a staging app URL + test account, a Jira project, a CI job, and a named champion at ~2 h/week.
- Marketplace publishing credentials (PAT retirement 1 Dec 2026 → Entra credential) and an Open VSX token.
- A frontend/VS Code engineer (≥ 50 %) for the chat-participant/TestController work; UX review time.
- Budget: LLM spend for pilots (estimate after 0.8 lands; expect roughly $5–40 per functional run at current prompt sizes) and ~$300–600/month for the cluster.

**Phase 2**
- Compliance platform (Vanta/Drata/Secureframe) + auditor for SOC 2 Type 1 → Type 2; an annual pen-test vendor.
- Legal: DPA, privacy policy, terms; a data-residency decision per org.
- Support tooling (status page, ticketing/Slack Connect) and an on-call agreement.
- Design-partner credits for 3–5 external teams; a technical writer for the docs site.
